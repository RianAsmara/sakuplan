# ADR-010: Deterministic financial engine, AI restricted to explanation

## Status

Accepted

## Context

The product's core promise (safe-to-spend, budget recommendations) requires numbers users can trust and reproduce. `CLAUDE.md`: "AI cannot be the source of truth for calculations." PRD `AI-002`/`AI-003`/`REC-007`: AI may receive minimized structured data and produce natural-language explanations, but its output is never parsed as authoritative monetary data, and deterministic recommendation generation must succeed even if the AI provider is unavailable.

## Decision

Implement `RecommendationService.Generate` and `PlanningService.SafeToSpend` as pure, dependency-free (recommendation) or read-only (safe-to-spend) deterministic functions — see [[Budget Recommendation Engine]] and [[Safe-to-Spend Engine]]. No AI/LLM call exists anywhere in the current money-calculation path. An AI explanation adapter (`REC-007`) is designed for but not yet built — it would sit strictly downstream of the deterministic engine's `ReasonCodes` output.

## Consequences

### Positive
- The financial engine is fully unit-testable and reproducible without any external API dependency — verified deterministic by `TestRecommendationIsDeterministicAndConservesMoney` (identical input → identical output).
- Product works completely without an AI provider configured (`AI-001`, `AI-005`) — there's nothing to fail over, since nothing calls out to AI yet.

### Negative
- The "explanation" layer that would make recommendations more approachable to end users doesn't exist yet — recommendations currently return only structured reason codes (e.g. `"MODE_BASED_SAVINGS_RATE"`), not human-readable text.

### Risks
- When the AI explanation adapter is eventually built, its integration point needs to preserve this boundary carefully — the adapter must only ever transform already-computed numbers into prose, never compute or adjust monetary values itself.
